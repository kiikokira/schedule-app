# Keio Logo Display Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ホーム上部の大学名見出しの上に慶應ロゴを大きく表示する

**Architecture:** `public/keio-logo.png`（提供済み・黒背景に金ペンマーク）を `HomeScreen` 先頭に `img` で表示するのみ。新規ロジックなし。既存バッジと同じ相対参照 `./keio-logo.png` を使う。

**Tech Stack:** React + TypeScript + Vitest

**Spec:** brainstorm短設計（会話承認済み・ファイルなし）。要件：ホーム上部・大学名見出しの上・大きく表示、`data-testid="keio-logo"`、`alt='慶應義塾大学ロゴ'`、幅100%・最大高さ約140px・`objectFit:contain`・角丸12、黒背景はバナー風に活かす、既存見出しは残す。

## Global Constraints

- 対象ファイルのみ `git add` する（`src/screens/HomeScreen.tsx`、`src/screens/HomeScreen.test.tsx`、`public/keio-logo.png`）。
- プッシュ前に `npm run build` が成功すること。
- プッシュはユーザーの許可後（スマホGitHub Pages反映のため本作業ではプッシュしない）。
- `src` は `./keio-logo.png` とする（既存バッジ `./badges/...` と同じ相対参照）。
- ロゴ掲載の商標判断はユーザーが引き受け済み。実装側で追加の権利処理はしない。

## Review Focus

- 画像ファイルが欠落・404でも `alt` テキストが出て壊れないことを期待する。
- 狭いスマホ幅でも横にはみ出さず縮小されることを期待する（幅100%＋contain）。
- 黒背景画像が明るい画面で浮きすぎないこと（角丸バナーとして見える）。
- 既存の `h1` 見出し・入試カウントダウン・ranking-card のテストが壊れないこと。
- 画像が重くて初回表示が遅くならないこと（PNG1枚・遅延なしで許容）。
