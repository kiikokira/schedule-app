# 参考書スケジュール管理アプリ 設計書

- 日付: 2026-09-20
- 状態: 設計合意済み（ユーザー確認待ち）

## 1. 目的と背景

高校2年生のユーザーが、慶應義塾大学環境情報学部への受験に向け、英語（＋小論文）の参考書を進めている。

現在は「参考書ごとに期限を決めて進める」方式だが、期限に間に合わずスケジュールがどんどん遅れていくのが課題。

本アプリは、参考書の進捗を記録し、「今日やるべきページ数」を自動計算して見える化することで、立てた期限を守れるようにすることを目的とする。

## 2. 前提・制約

- 使用端末: iPhone 13（Safari利用）
- 開発環境: Windows（Xcode不可のため、ネイティブiOSアプリは作らない）
- 構成: サーバーレスのフロントエンドのみの PWA とする
- 科目: 英語メイン（＋小論文集など少数）。科目分類は必須にしない

## 3. 技術構成

- React + TypeScript + Vite（PWAプラグイン）
- データ保存: Dexie.js（IndexedDB）
- 書籍メタ情報の取得: Google Books API（無料・キー不要・ブラウザから直接呼び出し可・CORS対応）
- ホスティング: GitHub Pages（無料・静的サイト）
- テスト: Vitest + React Testing Library

## 4. 画面構成（4画面）

### 4.1 ホーム（参考書一覧）
- 各参考書をカード表示: タイトル / 表紙サムネイル / 残りページ / 期限 / 今日の目標 / ステータス / 進捗バー
- 期限が近い順に並べる
- 遅れ・期限接近の参考書は上部で目立つように強調表示

### 4.2 参考書の詳細
- 「今日の目標」と「今日やったページ数」を記録する大きなボタン
- 1日1件の進捗記録（その日の記録がある場合、上書き）
- 残りページ、進捗バー、日々の進捗が分かる折れ線グラフ

### 4.3 参考書の追加・編集
- 検索タブと手入力タブの2パターン（下記「6. 参考書の追加フロー」参照）
- 編集時: タイトル、科目（任意）、総ページ数、開始日、期限日を変更可

### 4.4 設定
- バックアップの書き出し（JSONファイルダウンロード）
- バックアップの読み込み（JSONファイル選択 → インポート）
- 全データ削除

## 5. データモデル

### 5.1 参考書（Book）
| 項目 | 内容 |
| --- | --- |
| id | 自動生成 |
| title | タイトル（必須） |
| subject | 科目（任意。デフォルト「英語」） |
| totalPages | 総ページ数（1以上） |
| coverUrl | 表紙画像URL（任意） |
| startDate | 開始日（未設定なら作成日） |
| deadline | 期限日 |
| createdAt / updatedAt | 日時 |

### 5.2 進捗記録（ProgressRecord）
| 項目 | 内容 |
| --- | --- |
| id | 自動生成 |
| bookId | 参考書ID |
| date | yyyy-MM-dd |
| pages | 進めたページ数 |

1つの参考書の日付は1件まで。同日の再記録は上書きとする。

## 6. 参考書の追加フロー

### 6.1 検索で追加（メイン）
1. 追加画面の検索フォームにキーワードを入力
2. Google Books API で検索
3. 候補一覧（表紙サムネイル・タイトル・ページ数）から選択
4. ページ数が自動入力された状態で登録（ページ数が無い本はその場で手入力）

### 6.2 手入力で追加（フォールバック）
- 検索にヒットしない本（予備校オリジナル教材など）やオフライン時は従来どおり手入力

## 7. 目標自動計算ロジック

毎回表示時にその場で計算する。

- **完了ページ数** = その参考書の進捗記録の合計
- **残りページ** = max(総ページ数 − 完了ページ数, 0)
- **残り日数** = 期限日 − 今日
- **今日の目標** = ⌈残りページ ÷ 残り日数⌉（残り日数 ≤ 0 のときは「残りを全部やる」扱い）
- 基礎計算は純粋関数として実装（テスト対象）

### ステータス判定（3種類）
- **順調**: 完了していない かつ 今日までの実績が「ここまで進んでいるはずのページ数」以上
- **遅れ**: 実績が予定より下回っている
- **完了**: 完了ページ数 ≥ 総ページ数

※予定進捗は「開始日〜期限日」期間に対して、今日までの経過割合 × 総ページ数 で算出する。

## 8. エラー処理

- 検索失敗（オフライン・API一時停止）→「検索できませんでした」と表示し手入力へ案内
- 検索結果0件 → 手入力フォームを案内
- データ保存失敗 → 画面上にエラーメッセージ表示（データ喪失を黙らせない）
- 入力検証 → ページ数は1以上の整数、期限は開始日より後など
- バックアップ読み込み → 不正なファイルは弾いて「失敗」表示
- オフライン時 → 表紙画像は表示されないがアプリ動作は継続

## 9. 通知方針

- iPhone の PWA に確実に動くプッシュ通知は実装しない（制約のため）
- 代わりに「アプリを開くと遅れ・期限接近の参考書が目立つ」方式で対処

## 10. テスト

- 目標計算ロジックの純粋関数に対する境界テスト
  - 残り日数0、期限超過、完了時、開始日が未来の場合など
- 主要 UI 操作テスト（参考書登録、進捗記録）

## 11. 運用

- GitHub Pages に公開し、iPhone 13 の Safari で開いてホーム画面に追加
- ホーム画面追加後は起動用ファイルをキャッシュし、オフラインでも動作
- データは端末内保存。移行時に備え設定画面から書き出し/読み込みを行う

## 12. スコープ外（今回はやらない）

- クラウド同期・アカウント管理
- プッシュ通知
- 勉強時間の計測タイマー
- 複数科目の本格的な科目管理（科目は任意タグのみ）
