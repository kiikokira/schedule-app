# 島の土台（円形テラス式）設計書（2026-11-11）

## 意図・なぜ
- スマホで動く3Dワールドを一から作る。その第一歩として土台の島の形と高低差を作る。
- 既存のW1・newworldは使わない。新規ワールドとして始める。

## 目標
- 円形テラス式の島の土台：楕円＋赤岩の段々＋上・中・下の3段＋滝2本分の溝と池のくぼみ。
- 頂上スタート→池ゴールの特定の一本道を歩けること（道の地形・階段・橋の土台まで）。
- Blenderで編集でき、GLBとしてゲームに持ち込めること。

## 非目標・アンチゴール
- 非目標：木・滝の水・建物・小物の造形、RPG側の配線（graph接続・歩行制御）、ライティング本決め。
- アンチゴール：GLB肥大（上限5MB・目標3MBを超える作り）、写実PBR混ぜ、無確認の自動配置。

## 制約
- スマホ実機でラグらないことが最終判断。重くなれば段数・分割を削る。
- スタイライズド（参考画像寄りの独自造形）。特定作品の複製はしない。
- Blender 5.2＋Agent Bridgeで対話作成。1世界1アートスタイル。
- AGENTS.md運用：対象ファイルのみadd、push前にnpm run build成功、pushは許可後。

## 方式（Approaches）
- A. Blenderを見ながら対話で積む（採用）：段・道・滝位置を1つずつ作って確認。参考画像寄せしやすい。
- B. スクリプト一発生成（不採用・予備）：速いが味付けは後回し。数値が固まったら部分利用可。
- C. 既存アセット組立（除外）：一から作る方針と合わない。

## 決めたこと
- 形はA（円形テラス式）、道はA（頂上→中段→低地の一本道、池ゴール）。
- 既存ワールド不使用、土台のみ先行、細部は後段。

## ビルダーへの残し
- 島の直径・各段の高さ・道幅・階段と橋の位置の数値決定。
- 道の歩行用データ（中心線・始終点）の出し方。
- Blender編集用blend＋ゲーム用GLBの出力と置き場所、npm run build確認。
