# 新画像ロゴの一筆書きアニメ（ショートデザイン）

日付: 2026-11-15 / 対象: `src/components/OpeningSplash.tsx`＋新規派生アセット

## 意図・なぜ
- 起動ロゴをユーザ提供の新画像（X字の万年筆2本・尻くっきり）で、最初から最後まで一貫して表示する。
- アニメは現行維持：左ペン先→下端、次に右ペン先→下端の一筆書き。

## 決まったこと
- 方式は **A：提供画像を透過化＋定数調整して現行アニメに流用**。
- 提供ファイル：`public/スクリーンショット 2026-11-14 221850.png`（123×105・背景は不透明の白 242,244,248）。
- 派生アセット `public/keiologo-x.png`（透過化済み）を新規作成し、`LOGO_SRC` をそちらへ切替。日本語・空白入りの元ファイル名はコードから参照しない。

## 目標 / 非目標 / アンチ目標
- 目標：新画像で左→右の一筆書きが再生され、完成形で尻が欠けない。白い四角が出ない。
- 非目標：モックHTML改修、旧 `keiologo-pens.png` の削除（参照されなくなるが残す）、全suite衛生問題の解決。
- アンチ目標：白背景のまま表示、色・太さの描き直し、完成形が提供画像と別物になること。

## 制約
- 透過化は白抜きのみ（RGB は不変。縁のハローは許容）。
- `drawFrame(..., 1, 1)` は派生アセットと RGB 一致（Task 1 の alpha 正規化の性質を維持）。
- `prefers-reduced-motion`・5秒 `onDone`・`?retry=` 再取得の保証は維持。
- 現行定数は 280×272 前提（`TOP_BOTTOM_SPLIT_Y=150`、`ZONE_Y0/Y1=100/210`、`MIN_GOLD_PIXELS=20000` 総画素12915で到達不能）。123×105 に合わせ比例化等で調整する。
- 既存テストの前提を壊さないこと。比例化で振る舞いが変わるテストがある場合は更新してよいが、理由を記録する。
- 完了後は `npm.cmd run build` 成功確認、対象ファイルのみ `git add` して `main` へプッシュ。

## アプローチ（検討済み）
- A（採用）：透過化＋定数調整で現行パイプライン流用。差分最小・実画像主義維持。欠点：123px拡大でややぼやける可能性。
- B（不採用）：大きめ透過原画の再提供。画質最良だがもう一手間かかるため。
- C（不採用）：白背景のまま使う。起動画面ごと白化が必要でデザインが変わるため。

## ビルダーへの申送り（実装要点）
1. 白背景除去をピクセル操作の純粋関数（例：`removeWhiteBackground`、白判定は全ch高値のしきい値）として実装し、単体テストする。Node 等の一時スクリプトで `public/keiologo-x.png` を生成する（スクリプト自体はコミットしない。生成物のみ）。
2. `LOGO_SRC` を `./keiologo-x.png` に切替。旧定数を画像高さに追従させる（比例化）。`PHASE` 系の時間配分は変更しない。
3. 新アセット実寸での分類・描画の回帰テストを追加（尻の不透明化、左→右順序の維持）。
4. 既存テストが新定数で壊れる場合は最小限更新＋理由記録。
