# ページ範囲記録 — short design (2026-11-20)

- intent / why: 「何ページやったか」だけだとどこをやったか分からず続きが追いにくい。不便なので「何ページ〜何ページ」に変える。
- goals: 英文法ポラリス2を含む通常本（pages式）すべてで、開始ページ〜終了ページで記録できる。ページ数は自動計算（終了-開始+1）。一覧・詳細に範囲表示する。過去の件数記録はそのまま残す。
- non-goals: 反復型（cycles）への移行、周回管理、1日複数範囲、Home/TodayPlan・ランキング集計の変更、総ページ数を超えた繰り返しの扱い変更。
- anti-goals: 既存の完了数・目標・ゴースト・バックアップを壊すこと。記録済みを勝手に消す・書き換えること。
- constraints: pages式の保存則を維持（book+dateでupsert上書き、1日1件）。pagesは正として残し互換維持。pageFrom/pageToは任意追加でDexieスキーマ変更なし。バリデーションは単発と同一＋範囲チェック（1〜総ページ、開始≦終了）。全角数字正規化・iPhone入力配慮を再利用。スマホ・PWAで使えること。
- approaches:
  - 案A ページ範囲入力にする（採用）: 開始〜終了を入れてpages自動計算。既存データ・集計を壊さず最小変更。同日2範囲不可・周回なし。
  - 案B 反復型に寄せる: 全参考書を区画×周回化。複数件・周回に強いが移行と二重管理が大きく不採用。
  - 案C 併存: 件数or範囲を選択。柔軟だがUI複雑で不採用。
- decided (how): 案A。BookDetailScreenの単発フォームを「開始ページ・終了ページ」2欄にし、入力でページ数をプレビュー（例：120〜136→17ページ）。保存時はpages=終了-開始+1、pageFrom/pageToも保存。編集フォーム・まとめて記録モーダル（pages側）も同じ2欄化。記録一覧は「11/20 120〜136（17p）」、範囲なし旧記録は「17ページ」のまま表示。つづき入力（前回終了+1を次回開始に）は単発のみ対応。期間外日付は警告のみで保存許可（現行通り）。
- left to builder: pageFrom/pageToの型名・testid命名、プレビュー文言、開始＞終了の自動入替をするかエラーにするか（エラー想定）、Bulk側の行バリデーション文言、BookDetailScreen.test/BulkRecordModal.testへの追加ケース、backup検証への範囲許容。
