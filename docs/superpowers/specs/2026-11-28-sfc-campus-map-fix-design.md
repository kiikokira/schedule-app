# SFCキャンパスRPG 作り直し（地図・道・キャラ・移動）— 設計書

日付: 2026-11-28 / 状態: 草案（ユーザー承認待ち）
前提: `2026-11-25-sfc-campus-2d-rpg-design.md`（承認済み）の上に、実機確認で見つかった4件を直す。

## intent と why

- 2D RPGを実機で見たところ、次の4点が仕上がりとして不十分だった。
  1. 全体マップが色付きの箱だけで、道・木・地面が見えない。
  2. キャラの体に欠けがあり、リュックも描かれている。
  3. 十字キーと矢印ボタンでしか動かせず、指で自由に動かせない。
  4. 石の道に土の道が割り込み、Σ生協食堂（左上の黄色い屋根）から道が出ていない。
- 地図は、PDF2つ（バリアフリーマップ、案内図）と4枚目の画像（キャンパス構内案内図）を参考に作り直す。
- 変えないもの: EXPの原資（seasonStore）、クエストの枠と遷移、ホットスポットの種類、外部画像を背景に使わないこと。

## goals

1. **地図**: PDFの配置を色で読み取り、地形グリッドを作る。そのグリッドからコード描画の地図を作る。道・池・建物・木・草の位置が参考資料と一致する。
2. **道**: 石の道と土の道を同じタイル地図で扱う。交差や分岐で自然につながる。Σ生協食堂の入口から道を出す。
3. **全体マップ**: 本体と同じ地形描画を縮小して表示し、自分の位置とホットスポットを重ねる。
4. **キャラ**: 一体の連続したシルエットで描き直す。リュックは描かない。
5. **移動**: マップ上で指を置いた点を基準にスティックを出し、指の動かした方向へ歩く。短いタップは従来どおり経路で移動する。十字キーと矢印ボタンは画面から消す。キーボード（WASD/矢印）は残す。
6. **Eボタン**: 残す。近くにいるときだけ反応し、決定の操作として使う。

## non-goals

- PDFや画像をそのまま背景にしない。色の読み取り結果からコードで描く。
- 参考資料の建物上の文字（注記、番号、名称）は地図に描かない。ゲーム内のラベルは既存のLABELSを使う。
- 測量図の縮尺や正確な寸法は再現しない。ゲーム用のスケールに置き換える。
- EXP、クエスト、ランキング連携は変えない。
- 旧9ワールドのアセットには触らない。

## anti-goals（動いても失敗）

- 色の箱の地図に戻る、道が途中で切れる、建物の入口が塞がる。
- マップ上のドラッグでページがスクロールする。
- 地図の生成が実行時に走り、起動が重くなる（生成結果はコミット済みのデータにする）。
- 参考資料の文字が地図に写る。

## constraints

- 既存スタック: React 18 + Vite 5 + TypeScript 5.5 + vitest。実行時の新しい依存は追加しない。
- スマホ最優先。canvasは`touch-action: none`、操作ボタンは44px以上。
- `CAMPUS_LAYOUT`を単一の原資にしてきた方針は維持する。新しい原資は地形グリッドとし、建物・当たり判定・ホットスポット・ラベルはそこから導出する。
- 1マス=8ワールド単位。マップ1600×1200は200×150マスになる。道幅40単位は5マス、キャラ半径6単位は1マスより広く通れる。
- 対象ファイルのみ`git add`。`npm run build`成功後に`main`へプッシュする（AGENTS.md）。

## approaches（検討3案・選択B）

- **A. 座標の打ち直し**: 参考資料を見て建物と道の位置を手で測り直す。描画はそのまま使えるが、道の接続を手で合わせることになり、今回の不具合（道の割り込み、道の欠け）が再発しやすい。→ 不採用。
- **B. 色からの自動グリッド化（採用）**: 参考資料を高解像度の画像にし、1マスごとに地形の色で分類して地形グリッドを作る。道は同じタイルなので、交差や分岐は自然につながる。
- **C. 手書きの文字地図**: 参考資料を見ながら1マス単位の文字地図を手で書く。細かく調整できるが、正確さが出にくく修正の往復が多い。→ 不採用。

選択理由: ユーザーが参考資料の配置に忠実な地図を求めたため。Bは配置を機械的に取れ、道の接続問題を構造で防げる。

## 地形グリッド

### 入力

- **主**: バリアフリーマップ「大学部分拡大」（PDF1の2ページ目）。建物の外形、道、池、グラウンドが最も大きく描かれている。
- **補助**: 案内図（PDF2の1ページ目）。建物の番号と名称の対応、ヴィレッジの位置を確認する。
- **補助**: 4枚目の画像（構内案内図）。ギリシャ文字の名称と建物の形を確認する。
- **外周と周辺エリア**: PDF1の1ページ目（全体）、4ページ目（βヴィレッジ）、5ページ目（Hヴィレッジ）。
- 参考資料の文字（建物上の名称、番号、注記）は分類で無視する。名称は対応表に手で書く。

### 分類

- 1マスは、対応する画像領域の多数決で決める。
- 文字、番号、記号（濃いグレーや黒の細い線）は無視し、周囲4マスの多数色で置き換える。
- 色の分類（大学部分拡大の実物で確認済み）:
  - オレンジ（黄橙）の面 → 建物。PDFでは全棟が同じ色なので、色では棟を区別できない。オレンジの連結領域を1棟とし、白い道で区切られた単位ごとに建物IDを付ける。接している棟は連結領域が2棟にまたがるため、棟ごとに手で分割する（対応表に書く）。
  - 白 → 道。坂道の矢印（黄と赤のシェブロン）は白い道の上に重なっているので、白の道として扱う。
  - 水色 → 池。
  - 緑 → 草地（木の配置先）。PDFに土の色はないので、土は池の岸と外周に手で置く。
  - 左側の灰色の凡例パネルは地図ではないので対象外にする。パネルの下の西側の地形は、PDF1の1ページ目（全体）と案内図で補う。

### 出力

- `src/lib/sfcCampusGrid.ts`: 200×150の文字列配列。文字の意味は地形の種類を表す（草、石道、土、池、建物ごとのID、崖、外周など）。生成結果をコミットする。
- 生成は開発用スクリプトで再現できるようにする。アプリの実行時には走らせない。
- 建物の入口は、南側の辺の中央から2マス外（約12単位）の歩けるマスとする。1マス外では半径6の判定が入らず歩けないため。

## 描画

- `drawCampusBase`をタイル描画に置き換える。グリッドを走査し、各マスをシード付き乱数の模様で描く。
- 石道の縁は土色で縁取る。交差部は同じタイルなので割り込みが出ない。
- 建物は連結領域の外形から描く。既存の屋根・壁・窓の描き方（`drawBuildings`）を流用する。
- 木は草地のマスにだけ置く（既存の`placeTrees`と同じ見た目）。道・建物・池の上には置かない。
- 池は水のマスを既存の水の3層で描き、水に接する陸のマスは土色にする。

## 当たり判定

- グリッドのブロックマス（建物、池、崖、外周、木の幹）を横方向に連結して矩形にまとめ、既存の`rect`ブロッカーとして渡す。`collides`の変更は不要。
- 直前に入れた池の多角形判定（`poly`）は、グリッド化によって不要になる。削除する。
- テストで担保する:
  - 建物と池の内部はブロックされる。
  - 道の網は連結している（任意の道のマスから他の任意の道のマスへ歩いて行ける）。
  - 各ホットスポットの入口マスは歩行可能で、道の網に接続している。
  - Σ生協食堂の入口が道の網に接続している。

## ホットスポットとラベル

- 既存のHOTSPOTSのid、タイトル、文言は維持する。座標は建物の入口マスから導出する。
- 並木道の看板は、並木道の石道のマスに置く。鴨池は池の岸の歩けるマスに置く。
- ラベルは既存のLABELS（建物名とエリア名）を維持する。参考資料の建物上の文字は写さない。

## キャラクター（`sfcCampusSprite.ts`）

- 24×32を一体の連続したシルエットとして描き直す。腕、胴、頭の継ぎ目を同じ色の連続領域で埋める。
- リュックを描かない。背面向きも、髪と紺の服だけで描く。
- 4方向×2フレームの歩行、既存の影はそのまま残す。
- 検証: オフスクリーンに描いたスプライトを拡大して画像で確認する。

## 移動（入力）

- 十字キーと矢印ボタン（D-pad）は画面から削除する。
- マップ（canvas）で pointerdown したら、その位置を基準点とし、スティックを表示する。pointermove で基準点からのベクトルを取り、長さ（最大40 CSS px）に応じた速度で歩く。pointerup で止める。
- 指がほとんど動かず（10px未満）、250ms以内に離した場合はタップとして扱う。既存のA*で目的地まで歩く。
- ホットスポットのタップは既存の挙動を維持する（範囲内なら開く、範囲外なら歩いて着いたら開く）。
- キーボード: WASD/矢印で移動、Enter/Spaceで決定、Eで決定、Escでパネルを閉じる（既存）。
- canvasに`touch-action: none`を付け、ドラッグ中にページがスクロールしないようにする。
- パネル表示中と全体マップ表示中は入力を無視する（既存のpaused）。

## 全体マップ

- 本体と同じ`drawCampusBase`の結果を、枠内に全体が収まるように縮小して描く。
- 自分の位置（小さな学生マーカー）とホットスポット（金の丸）を重ねる。
- 「色の箱」の描画は削除する。
- 閉じる操作は既存のヘッダーの閉じるボタンを使う。

## 変更しないもの

- seasonStoreのEXP、`levelForExp`、クエストの枠（最大4件）、枠なし・全完了の状態、TodayPlan/BookDetailへの遷移。
- ランキング画面（RankingScreen）への統合。

## 検証

- `npx vitest run`が全件通ること、`npm run build`が成功すること。
- 新規テスト: グリッドの寸法と文字種、建物入口の到達性、道網の連結、建物と池のブロック、ドラッグのベクトル計算（純粋関数）。
- 目視: ブラウザで全体マップ、本体、キャラ、道の接続を確認する。スマホ実機の確認はユーザーが行う。

## 決めたこと（著者の判断。異論があれば教えてください）

1. **生成の方式**: 開発用のNodeスクリプトで、PNGの読み込みに`pngjs`を開発依存として使う。実行時の依存は増えない。
2. **道の種類**: PDFの白い道はすべて石道にする。土は池の岸、外周、未舗装の小道だけに使う。
3. **D-padの削除**: 画面から完全に削除する。キーボード操作は残す。
4. **全体マップの建物チップ一覧**: 残す。

## builder check の反映（決定事項。[著者判断]は異論があれば変更できる）

- [著者判断] **対象範囲**: 大学部分拡大（PDF1の2ページ目）の凡例を除いた部分をマップの主体にする。凡例の裏側の西側は草地で埋める。
- [著者判断] **マップの寸法**: 切り抜いた範囲の縦横比に合わせてグリッドの寸法を決める（4:3に無理に合わせない）。1マス=8単位は変えない。
- [著者判断] **建物**: 白い道で区切られたオレンジの連結領域を1棟とする。接して1領域になる棟は、領域の形で手動分割する（対応表に明記）。名前のない棟は名前なしで残す（ラベルは付けない）。
- [著者判断] **建物IDと名前**: 既存のbuilding IDを正本にする。名前は大学部分拡大の表記に合わせる。案内図の番号は対応表の検証に使う。
- [著者判断] **白い文字**: 建物上の白い文字は、連結領域を取る前に、周囲の色で置き換える（建物の内側として埋める）。
- [著者判断] **入口と歩行**: 入口は2マス外。道網の連結テストは、円（半径6）の判定で行う。道は最低2マス幅を保つ（細い隙間は生成時に広げる）。
- [著者判断] **A*の刻み**: 8単位（既存の16から変更）。
- [著者判断] **外周**: 外周の1マス帯（約48単位）を土色の崖として描き、ブロックする。参考画像3の土の縁に合わせる。
- [著者判断] **木**: PDFに木は描かれていないので、木は草マスに既存の`placeTrees`（シード付き）で置く。幹の当たり判定はそのまま`placeTrees`の結果から作る（グリッドからは導出しない）。テストは「木は草マスの上だけ」「道・建物・池の上にない」を確認する。
- [著者判断] **ツール**: 変換の入力PNG（大学部分拡大を高解像度で書き出したもの）は`artifacts/sfc-campus-source/`にコミットする。生成スクリプトは`pngjs`だけを開発依存にする。PDFからPNGへの変換は一回限りの手順として、設計書に手順を書く。
- [著者判断] **旧データの扱い**: 既存のHOTSPOTSの文言は維持する。SPAWNは正門前の道に移す。
