# ペン尻の欠け修正＋左→右の一筆書きアニメ維持（ショートデザイン）

日付: 2026-11-15 / 対象: `src/components/OpeningSplash.tsx`（元画像: `public/keiologo-pens.png`）

## 意図・なぜ
- 起動ロゴ（黄色い万年筆2本のX）の下端・ペン尻の丸みが黒背景に溶けて消えかけて見える。
- 尻まで欠けなくくっきり表示し、アニメーションとして成立させる。

## 決まったこと
- 描画順は **左ペン先→下端、次に右ペン先→下端**（現行実装の順番通り）。
- 方式は **A: 現行の実画像素ピクセル方式を直す**（トレース・描き直しなしの方針を維持）。

## 目標 / 非目標 / アンチ目標
- 目標: 完成フレームでペン尻が欠けずに表示される。アニメは左→右の一筆書きのまま。
- 非目標: ロゴ自体のデザイン変更、再生ボタン等のUI追加、モックHTML（`pen-options*.html`）の改修。
- アンチ目標: 尻を太らせる・色を変えるなど元画像から逸脱する見た目。完成形が元PNGと別物になることは失敗。

## 制約
- `public/keiologo-pens.png` はそのまま使う（実画像主義）。
- `drawFrame(model, ..., 1, 1)` は元画像と RGB ピクセル一致（alpha のみ金の縁を 255 に正規化。既存テスト [C1] の性質を維持）。
- `prefers-reduced-motion` 対応・5秒で必ず `onDone` の保証は壊さない。
- 既存テスト `src/components/OpeningSplash.test.tsx` を維持・拡張する。

## アプローチ（検討済み）
- A（採用）: 金判定・前面グロー透過・終端描画の見直しで尻の暗部/低alphaを落とさない。見た目不変・差分最小。
- B（不採用）: 尻だけ丸キャップで補描画。確実だが実画像主義から外れるため。
- C（不採用）: 終了時に `<img>` 実画像へスナップ。簡単だが切替の違和感が出るため。

## 調査結果（2026-11-15、node+zlib で `public/keiologo-pens.png` を実測）
- 画像は 280x272・RGBA。金色（maxRGB>16）の最終行は y=255 で、y=256〜271 の16行は完全な空き（透明/黒）。
- 尻部の縁ピクセルは RGB=(241,196,0) のまま alpha=16〜143 の半透明フェザー状。
  黒背景 + `drawFrame` の `alpha * am` 合成で黒に溶けて「消えかけ」に見えるのが主因。
  `GOLD_THRESHOLD=16` は RGB 判定なので該当画素はモデルに含まれる（判定落ちではない）。
- よって修正は「金画素の alpha を分類時に 255 へ正規化（RGB は不変）」とする。
  完成フレームの RGB は元PNGと一致し、alpha のみ縁が不透明化される。
  既存テスト [C1] はモデルを手作りするため影響なし。16行の空きパディングは仕様として残す。
## ビルダーへの申送り（実装手順の要点）
1. （済：上記調査結果を使う。新規調査は不要）
2. `classifyPenPixels` で金画素の alpha を 255 に正規化して格納する（RGB は元値のまま）。
   `drawFrame` の描画式自体は変えない。完成フレームの RGB ピクセル一致は維持。
3. 描画順（左ペン先→下端→右ペン先→下端）をテストで固定する
   （`phaseProgress` の先行関係、`classifyPenPixels` の nib1=左ペン対応）。
4. 尻領域の代表ピクセルが完成フレームで不透明に描画されるテストを追加する。
5. `npm run build` の成功を確認する。AGENTS.md に従い対象ファイルのみコミットし `main` へプッシュする。
