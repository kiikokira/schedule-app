# 今日の計画(タイムテーブル)・自動組み込み・自動スケジュール設計書

- 日付: 2026-09-21
- 状態: 設計合意済み

## 1. 目的と背景

現在のアプリは「参考書ごとに期限を決め、今日やるべきページ数を自動計算して進める」方式。これに以下の2つの新機能を追加する。

- **機能①: できなかった勉強の自動組み込み**
  前日の「予定ページ数 − 実績ページ数」の不足分を、翌日以降の空き時間へ自動再配置する。
- **機能②: AIによる自動スケジュール生成**
  参考書の残りページ・期限・ユーザーの空き時間から、「毎日どの本を、何ページ、何分、何時からやるか」を自動生成する。

方針として、ユーザーのやり取り回数を極限まで減らし、**AI(アルゴリズム)の提案がそのまま採用されることをデフォルト**にする。同時に、ブラウザ内で完結する以上、**重く・ラグくならないこと**も要件とする。

## 2. 前提・制約

- サーバーレス PWA(React + TypeScript + Vite、Dexie/IndexedDB、GitHub Pages)
- 使用端末: iPhone 13(Safari)。オフライン動作必須
- AI は **ブラウザ内の最適化アルゴリズム**(外部LLM APIを使わない)
  - 理由: オフライン可・待ち時間なし・無料枠の制限なし・APIキー不要
- 依存パッケージは追加しない(すべて自前実装)

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| 空き時間(スロット) | 学習可能な時間帯。15分刻み。曜日ごとに設定し、当日上書きできる |
| タイムテーブル | 1日分の学習計画。各行 = 開始~終了時刻・本・予定ページ数 |
| 不足分 | ある日の「予定必要ページ数 − 実績ページ数」の正の差 |
| 所要速度 | 本ごとの「1ページあたりの所要時間」(分)。実績から自動学習する |
| 再調整 | 本の追加・編集後に、全本のバランスを取って配分を再計算すること |

## 4. アーキテクチャ

- 既存の「スケジュール(Bookエントリ)+ 進捗記録」を正のデータとする
- 新規に「週間アベイラビリティ」「本ごとの所要速度・優先度・配分比率」「調整履歴」を保持
- タイムテーブルは**画面を開くたび純粋関数で再計算**し、保存しない
  - 真実源: 「設定(空き時間・速度・優先度)」と「実績(進捗記録)」のみ

## 5. データモデル

### 5.1 空き時間(availability テーブル・新規)

| 項目 | 内容 |
| --- | --- |
| id | 自動生成 |
| weekday | 0-6(曜日)。当日上書きの場合は null |
| date | date 上書きの場合は 'yyyy-MM-dd'、通常は null |
| start | 'HH:mm' |
| end | 'HH:mm' |

- 曜日ごとの基準スロットと、特定日の上書き(当日上書き)を同一テーブルで表現する
- 上書き(weekday = null かつ date あり)が、該当日に優先される

### 5.2 BookData への追加フィールド

| 項目 | 内容 |
| --- | --- |
| minutesPerPage? | 1ページあたりの所要時間(分)。省略時は科目別デフォルト |
| priority? | 配分優先度。省略時は期限順 |
| allottedRatio? | ユーザー指定の配分比率(0-1)。省略時は自動平準化 |

### 5.3 調整履歴(adjustments テーブル・新規)

| 項目 | 内容 |
| --- | --- |
| id | 自動生成 |
| date | 'yyyy-MM-dd' |
| bookId | 対象の参考書 |
| kind | 'ratio' \| 'priority' \| 'override' |
| value | 数値 |

- ユーザーが再調整で行った直接修正を記録し、翌日以降の自動計算にも学習反映するための元データ

### 5.4 タイムテーブル

- 保存しない。`generateDayPlan(...)` の戻り値としてのみ存在する

## 6. アルゴリズム: `generateDayPlan`

画面を開くたび、または再調整時に呼ばれる**純粋関数**。

**入力**: 空き時間 / 本一覧(所要速度・優先度・比率)/ 進捗記録 / スケジュール(Bookエントリ)/ 今日

### 6.1 手順

1. **残量計算**: 各本の残りページ = totalPages − 進捗合計。期限切れや開始日超過の未着手本も対象に含める
2. **優先度付け**: priority設定があればそれを使う。なければ期限が近い順、期限超過が最優先
3. **基準配分**: 残りページ ÷ 残り日数 = 本ごとの1日必要量
4. **時間→ページ変換**: 15分スロット × (1 ÷ minutesPerPage) = そのスロットでこなせるページ数
5. **繰り越し(機能①)**: 過去の日で「実績 < 予定必要量」の不足分を、今日以降の空き時間へ上方加算(優先度の高い本から)
6. **初期案生成**: 空き時間に優先度順+平準化で本を詰める。連続スロットはまとめて1本にする
7. **評価関数で採点**: 期限順守率 / 1日の負荷の偏り / 本の切り替え回数 / 不足繰り越しの解消度 を指標化
8. **局所改善**: スコアを上げる向きに微調整を反復(負荷の高い日を減らす、連続配置の最適化など)。打ち切り回数を明示し、最良スコアの案を採用
9. **出力**: 今日のタイムテーブル(各行 = 開始時刻・本・予定ページ数)と、未来数日分のサマリ(日ごとに「本・分・ページ」)

### 6.2 境界ケース

| ケース | 動作 |
| --- | --- |
| 今日の空き時間が0 | 「今日は割り当てなし」と表示し、明日以降へプッシュ |
| 全本が期限超過で空き時間不足 | 期限超過の本を最優先で配分し、残りは翌日へ |
| 所要速度が未設定 | 科目別デフォルト(英語5分/頁 など)を使用。実績が蓄積すれば更新 |
| 空き時間設定が未登録 | 「空き時間を設定してください」案内と設定への導線。タイムテーブルは空表示 |
| 割り当てが空き時間を超える | あふれ分を翌日へ自動プッシュ(無限ループなし) |

### 6.3 所要速度の学習(記録時)

- 行記録時に、その日に割り当てられた**その本のトータル時間**を分母、**その日記録したページ数**を分子として実効速度を算出
- 実効速度が現在値と異なる場合、加重平均で `minutesPerPage` を更新(遅い実績も反映)
- 記録はページ数のみ ※時間の実測は記録しない

## 7. パフォーマンス要件

- 計算はすべてローカル・同期・軽量。`generateDayPlan` の1回の実行は **数ms以内** を目標とする
- 局所改善の反復回数に上限を設け(数千回程度)、UIスレッドをブロックしない
- 本の数は現実的に数十冊以下が前提(計算量の上限を保証)
- タイムテーブル描画は React 仮想DOM で処理。行数は 日数 × スロット数 に制限
- IndexedDB の書き込みは記録時のみ(本ごと1日1件)。タイムテーブル再計算は読み取りのみで保存しない
- `generateDayPlan` に軽い実行時間ログを入れ、パフォーマンスが要件を満たすことをテストで確認できるようにする
- 依存パッケージは追加しない(自分の実装のみ)ため、バンドルサイズの増加は小さい

## 8. 画面構成

### 8.1 新規: 今日の計画画面(TodayPlanScreen)

- `App.tsx` に `{ name: 'today' }` ルートを追加。ホームのフッターに「今日の計画」ボタンを追加
- 画面を開くたび `generateDayPlan` を呼び、最新状態で再計算
- 上部: **今日のタイムテーブル**(15分刻み)
  - 各行: 開始~終了時刻・本のタイトル・予定ページ数、および記録入力(その日のページ数。従来の進捗記録に累積加算)
- 下部: **未来数日分のサマリ**(日ごとに「この本を○分・○ページ」)。不足分の再配置先が見える
- 昨日以前に不足がある場合、**「昨日の不足分を○日の空き時間に再配置しました」** の案内を表示
- 「空き時間の設定」への導線を含む

### 8.2 既存画面の変更

- **PlanScreen(計画)**: 「空き時間の設定」セクションを追加。曜日ごとの時間帯の追加・削除、特定日の上書き(当日上書き)の設定・編集
- **BookFormScreen(追加・編集)**: 「1ページあたりの所要時間」の初期値入力フィールド(省略時はデフォルト)。保存後、**「配分を再調整」ボタン**を表示
- **HomeScreen**: 既存の進捗バー等は維持。フッターに今日の計画への導線を追加

### 8.3 再調整機能

- **入口**: 参考書の追加・編集保存後のボタン押下
- **フロー**
  1. 現在の計画(調整前)を保持したまま、新状態で再計算した**調整後の提案**を生成
  2. 比較表示: 調整前 → 調整後の差分をハイライト
  3. ユーザーの直接修正:
     - 行の本を差し替え
     - その日の配分(ページ数・継続時間)を増減
     - 配分比率・優先度の調整(この本を優先させたい、比率を下げたい等)
  4. 「この配分率で反映」で確定。修正内容は `priority` / `allottedRatio` / `adjustments` に保存され、翌日以降の自動計算にも学習反映
  5. 「○冊の配分を更新しました」と報告
- **やり取り最小化の原則**: 提案が「そのまま最良」と評価される場合は確認なしで表示(比較・修正モードに遷移しない)。修正が必要な場合だけ比較修正モードへ

## 9. エラー処理

- 空き時間未設定 → 設定への導線 + 空表示
- 所要速度未設定 → 科目別デフォルト
- 記録時に本が存在しない → 無視
- 割り当てがあふれる → 翌日へプッシュ(循環なし)
- 学習の速度更新が異常値(< 0.1分/頁 など)→ 更新しない

## 10. テスト(Vitest)

- `generateDayPlan` の純粋関数テスト:
  - 基本配分 / 期限超過優先 / 平準化 / 繰り越し(昨日の不足が今日に加算)/ 0スロット / パンク時の翌日プッシュ / 評価関数の単調性 / スコアが最良案の採用
- 所要速度の学習テスト(実績速度の反映・遅い実績での更新・異常値の無視)
- availability の保存と当日上書きのテスト(曜日基準と上書きの優先関係)
- TodayPlanScreen のUIテスト(タイムテーブル表示・行記録・再配置案内・空き時間未設定の案内)
- BookFormScreen の再調整ボタン、PlanScreen の空き時間設定 UI テスト
- パフォーマンス要件: `generateDayPlan` の実行時間が数ms以内であることを計測テストで確認
